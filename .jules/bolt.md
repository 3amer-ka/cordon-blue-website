## 2026-04-06 - Replacing background-image with lazy-loaded <img> tags
**Learning:** Native `loading="lazy"` on semantic `<img>` tags provides significant performance improvements for below-the-fold content compared to CSS `background-image`, which lacks native lazy-loading support in most browsers. In this codebase, multiple below-the-fold images were being eagerly loaded due to the use of `background-image` within `div` elements, impacting initial page load time. Converting these to `<img loading="lazy">` reduces the initial payload and network requests on load. When verifying this via Playwright, remember headless browsers may still download them eagerly, so checking the HTML output directly is more reliable. Also, explicitly adding `object-cover w-full h-full` ensures the images replicate the `bg-cover bg-center` visual behavior precisely.

**Action:** Replace `div`s styled with `background-image` below the fold with `<img>` tags implementing `loading="lazy"`. Be careful to retain the existing classes, particularly sizing and layout (e.g. `object-cover object-center w-full h-full` instead of `bg-cover bg-center` if replacing the parent or using absolute inset).

## 2026-04-26 - Render Build Fallback
**Learning:** Render defaults to calling `npm run build` if the deployment environment is Node.js, even if `render.yaml` specifies a custom `buildCommand`. If a `package.json` file is present but lacks a `"build"` script, the deployment will fail immediately with "Empty build command; skipping build" and a missing publish directory error.
**Action:** When working with custom static build commands, always map them to a `"build"` script in `package.json` to ensure compatibility with PaaS defaults.

## 2026-05-15 - Optimizing Pillow Image Processing Loops
**Learning:** In Pillow (PIL) image processing loops, repeatedly resizing images to the same dimensions (like a fallback matching an already generated responsive size) is computationally expensive. Caching intermediate resized `Image` objects in a dictionary keyed by dimensions `(w, h)` avoids redundant `.resize()` operations. Additionally, when saving images as JPEG, non-RGB modes (like RGBA) will crash the save operation; always ensure images are converted to RGB (`img.convert('RGB')`). Finally, robust handling of unreadable or corrupt files requires a broad `Exception` handler around `Image.open()` (catching cases like `UnidentifiedImageError`), rather than just checking for `FileNotFoundError`.
**Action:** When implementing or optimizing image processing with Pillow, cache intermediate resized images by their dimensions. Always convert images to 'RGB' before saving as JPEG, and wrap file opening in a broad exception handler.

## 2026-06-29 - Tailwind CSS Missing on Production Deploy
**Learning:** During Render deployments with Node.js, the environment defaults to `NODE_ENV=production`. This configuration automatically prunes any packages listed under `devDependencies` in `package.json` during the `npm ci` step. If the build command relies on tools like Tailwind CSS, and they are located in `devDependencies`, the build will fail with a "command not found" error because the tool wasn't installed. Moving these necessary build tools (like `tailwindcss`, and its plugins) into `dependencies` ensures they are installed even during production deployments.
**Action:** When build tools like Tailwind CSS are required during the build phase of a deployment, ensure they are placed in `dependencies` rather than `devDependencies` within `package.json` to prevent them from being pruned by standard `NODE_ENV=production` environments.
## 2024-07-28 - Swallowed Exceptions in ThreadPoolExecutor
**Learning:** When using `executor.map()` with Python's `concurrent.futures.ThreadPoolExecutor`, it returns an iterator. If the iterator is not consumed, exceptions raised within the worker threads (like `FileNotFoundError`) are silently swallowed, causing scripts to exit successfully even when errors occurred.
**Action:** Always consume the generator returned by `executor.map()` (e.g., by wrapping the call in `list()`) to ensure exceptions bubble up to the main thread appropriately, maintaining robust error handling.
